# Deploying ForgeFit on Render (free, no credit card)

Render builds from this GitHub repository; there is nothing to upload by hand.
`render.yaml` at the repo root describes everything Render creates:

```
Browser ──HTTPS──► forgefit.onrender.com        (static site: the React app)
                     │ /api/*, /media/* rewritten
                     ▼
                   forgefit-api.onrender.com    (free Python web service: FastAPI)
                     │
                     ▼
                   Neon free Postgres           (Render's free Postgres is deleted after 30 days)
```

The static site forwards API calls instead of the browser calling the API
directly. Two `onrender.com` subdomains are different *sites* to a browser, so
a direct call would need a `SameSite=None` cookie, which Safari blocks.

## 1. Database: Neon

1. Sign up at neon.com with GitHub. No card is needed.
2. Create a project. Region: **AWS Asia Pacific (Singapore)**, next to the API.
3. Copy the connection string (`postgresql://…?sslmode=require`). The app
   points it at psycopg 3 itself, so paste it as Neon gives it.

## 2. Render: create both services from the Blueprint

1. Sign up at render.com with GitHub and allow access to the ForgeFit repository.
2. **New → Blueprint**, pick the repository and branch `main`.
3. Render lists `forgefit-api` and `forgefit`, then asks for the values
   marked `sync: false`:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | the Neon connection string |
   | `OPENAI_API_KEY` | your OpenAI key |
   | `USDA_FDC_API_KEY` | your USDA FoodData Central key |
   | `NUTRITION_APP_ID`, `NUTRITION_APP_KEY` | your nutrition API credentials |

   `JWT_SECRET` is generated by Render. Never put a secret in `render.yaml`.
4. **Apply.** The API build takes a few minutes. Its start command runs
   `alembic upgrade head` first, so the empty Neon database gets every table.

## 3. Check the URLs

Render uses the service name for the URL when it is free. If either service
got a different URL, change these three places in `render.yaml`, commit and
push (Render redeploys on every push to `main`):

- `CORS_ORIGINS` → the static site's URL
- both rewrite `destination`s → the API's URL

## 4. Smoke test

1. `https://forgefit-api.onrender.com/api/health` returns `{"status":"ok", … "env":"production"}`.
2. `https://forgefit-api.onrender.com/docs` returns 404 (docs are off in production).
3. Open `https://forgefit.onrender.com`, register, log a Smart Log sentence,
   reload the page and check you are still signed in (the refresh cookie works).

## 5. Keep the API awake

A free web service sleeps after 15 minutes without traffic, and waking it
takes up to a minute, so the first request after a quiet spell can fail. Add a
free monitor at uptimerobot.com: HTTP(s), URL
`https://forgefit-api.onrender.com/api/health`, every 5 minutes. One service
running all month fits inside Render's 750 free hours.

## 6. Check the rate limiter sees real visitors

`TRUSTED_PROXY_HOPS=2` assumes two proxies (the static site's rewrite, then
Render's load balancer). To confirm: from a phone on mobile data, sign in with
a wrong password 11 times until it answers "too many attempts". Then sign in
from a laptop on Wi-Fi straight away.

- Laptop signs in: correct.
- Laptop is blocked too: every visitor shares one limit. In the Render
  dashboard set `TRUSTED_PROXY_HOPS` to `1` (then `3`) and repeat.

## 7. Before sharing the link

- OpenAI dashboard → Limits: set a monthly budget. Anyone who registers uses your key.
- Rotating `JWT_SECRET` (Render → forgefit-api → Environment → Generate) signs every user out.

## Free-tier limits worth knowing

- API: 512 MB RAM, sleeps when idle, disk wiped on each deploy (the app keeps
  nothing on disk; exercise images ship with the repository).
- Neon: 0.5 GB storage on the free plan, compute pauses when idle and resumes on the next query.
- There are no automatic backups on either free plan. For a manual one, run
  `pg_dump "<Neon connection string>" | gzip > forgefit-$(date +%F).sql.gz`
  from any machine with the PostgreSQL client installed.
  (`deploy/backup.sh` is for the Docker deployment only.)
