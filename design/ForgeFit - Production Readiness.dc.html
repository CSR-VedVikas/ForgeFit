What replaces it is a shorter list, and one item on it needs doing before you read the rest of this page.

Do this first — today

backend/.env holds three live credentials in plain text: an OpenAI project key, a Nutritionix live key, and the JWT signing secret. The file sits in the working tree beside .env.example.

Rotate all three at the provider today, whether or not the file was ever pushed. An exposed OpenAI project key is a billing liability, and a leaked JWT_SECRET lets anyone mint a token for any user_id — every account, silently, with no trace in the logs.

Then: confirm .env is in .gitignore; if it was ever committed, purge it from history rather than deleting it in a new commit; and move the production values out of the repo entirely — a systemd EnvironmentFile outside the checkout, or your host's secret store. forgefit.db and forgefit_clean.db are in the tree too and carry user rows and password hashes; they belong in .gitignore as well.

1 · What the July audit flagged and the repo has since fixed

Worth stating plainly, because it changes the size of the remaining job. The backend is further along than the completion plan assumed.

Interactive docs exposedFixed. main.py sets docs_url and redoc_url to None whenever is_production, regardless of enable_docs
Stack traces to clientsFixed. The catch-all handler logs the exception and returns a bare {"detail": "Internal server error"}
No rate limitingFixed. slowapi at 120/min default, 10/min on auth, 20/min on the NLP route, with the 429 handler mounted
No security headersFixed. SecurityHeadersMiddleware sets nosniff, X-Frame-Options: DENY, a referrer policy, a permissions policy, and HSTS on https
Password reset leaked the tokenFixed (S1). Tokens are hashed at rest, single-use, prior unused ones invalidated on reissue, and the response is identical whether or not the account exists
No request correlationFixed. Structured JSON logs with an X-Request-ID echoed on every response, plus Sentry when a DSN is set

2 · What actually blocks the release

#BlockerWhere, and the fix
PR1 Live secrets in the tree See the panel above. Rotate, gitignore, move out of the checkout
PR2 Nothing refuses to boot with dev config config.py defaults jwt_secret to "dev-secret-change-me". A production deploy that forgets one env var starts happily and signs tokens with a value that is public in the source. Add a pydantic model_validator that raises on start when is_production and any of: the secret is the default or under 32 chars, database_url is sqlite, enable_docs is true. Failing to boot is the correct behaviour — a misconfigured server that runs is worse than one that doesn't
PR3 CORS regex survives into production cors_origin_regex defaults to the LAN development pattern, and main.py passes it whenever it is non-empty, alongside allow_credentials=True. Any host on a private-range address at :5173, :4173 or :8080 is a trusted, credentialed origin — including an attacker on the same coffee-shop network. Force it to None when is_production and require an explicit allowlist
PR4 Two sources of schema truth main.py calls Base.metadata.create_all(bind=engine) on every startup while alembic/versions/0001_initial.py exists. create_all creates missing tables but never alters existing ones, so migrations look unnecessary right up until the first ALTER — which is the N1–N5 migration — and then the schema silently drifts per environment. Delete the create_all call; make alembic upgrade head a deploy step
PR5 No refresh token, no revocation config.py carries refresh_token_expire_minutes, but auth.py only ever mints an access token, and routers/auth.py has no refresh route. At the 60-minute default a user is signed out mid-workout, roughly hourly. There is also no jti and no denylist, so logout is client-side only and a stolen token stays valid its full life. This is the decision that gates the frontend wiring — see §4
PR6 SQLite db.py opens a single file with check_same_thread=False. It will not take concurrent writes across uvicorn workers; a set logged during a nutrition write can hit database is locked. Postgres before launch, and 0001_initial re-run against it rather than a copied file
PR7 No TLS at the edge deploy/nginx.conf listens on 80 only. HSTS in the app is conditional on request.url.scheme == "https", so today it never fires. Add the TLS server block and the 80→443 redirect, plus client_max_body_size and gzip on /api/
PR8 Silent password truncation auth.py hashes password[:72]. A user with a 100-character passphrase is authenticated on its first 72 characters, and two different passphrases sharing a prefix both work. Reject over-72-byte passwords at the schema, or SHA-256 pre-hash before bcrypt. Small, but it is a silent weakening of exactly the users who chose the strongest passwords
PR9 Naive UTC timestamps auth.py uses datetime.utcnow() — deprecated in 3.12 and timezone-naive. Move to datetime.now(timezone.utc) before it meets a non-UTC host
PR10 Wrong nutrition base URL in .env The committed .env points NUTRITION_API_BASE_URL at the provider's /docs page, where config.py defaults to /v2. Any environment loading that file sends food lookups to a documentation page. Config bug rather than a security one, but it will read as a broken Fuel screen
PR11 Rate limiting is per-IP only rate_limit.py keys on get_remote_address. Behind the nginx proxy every request arrives from the proxy's address unless the app is told to trust X-Forwarded-For, which collapses all users into one bucket. Run uvicorn with --proxy-headers and a trusted-host list, and verify the limiter sees real client IPs before you rely on the 10/min auth limit

3 · The order to do them in

The ordering is not by severity. It is by what would have to be redone if taken later — PR5 changes how every screen holds a session, so it precedes the wiring; PR4 precedes the migration because running the migration under create_all is how environments diverge.

Sequence

Today — PR1. Rotate the three credentials, gitignore .env and the two .db files, purge from history if needed. Nothing else on this page matters while a live OpenAI key is in a checkout.

Day 1 — PR2, PR3, PR4, PR10, PR11. Config guards, the CORS default, drop create_all, fix the base URL, prove the limiter sees real IPs. All small, all in three files. After this the app is safe to put on a network.

Days 2–4 — PR5, PR8, PR9. Settle the token model: refresh route, jti plus a denylist table, logout that actually revokes. Decide storage at the same time — see §4. Password and timestamp fixes ride along.

Days 5–17 — wiring. Read-only screens, then writes, then the single migration carrying N1–N5, the records gap R1, and W1, then the queue-backed screens, then Fuel. The frontend contract is already written: frontend-api/client.js, endpoints.js, session-queue.js, against the 32 endpoints in the Track B document.

Days 18–25 — PR6, PR7. Postgres, TLS, packaging, a restore-from-backup rehearsal, and the release checks.

4 · The one decision that is still yours

Where the token lives, and it has to be answered before day 2 because everything downstream inherits it. httpOnly cookie: immune to XSS token theft, needs CSRF protection and a same-site story, and constrains the store-app path. Bearer token in storage: what frontend-api/client.js is written against today, simplest to wire, and readable by any script that gets onto the page. If ForgeFit ships as a store app rather than a web app, the answer is the platform keychain and neither of the above — which is why the web-or-store question, still open from 28 July, has to be settled in the same conversation.

Everything else is specified. Nine schema gaps with the smallest fix for each, 32 endpoints mapped field by field to nine screens, and a designed state for every condition the app can be in — cold cache, unreachable server, expired session, queued writes, read-only past days, server refusals, empty ranges.

What none of it is, yet, is wired. The prototype runs on fixtures, and the honest read of this page is that the design and the specification are release-ready while the service is about three weeks and one owner away. PR1 is the exception to the schedule: it is not three weeks away, it is today.
